## 0. How the work is organised

**Orchestration:** yes — 17 work packages in 7 waves (2 Haiku, 10 Sonnet, 5 Opus), plus fix packets during the build loop. The app is about 27,000 lines of Swift and nearly every fix depends on one shared change (the new data model), so the work splits naturally into a foundation, several independent pipelines that can be built in parallel against a written-down interface, and a screen layer on top. Model choice follows Jack's instruction: Opus 5.5 at medium effort only for the five hardest packages, Sonnet 5.5 at medium effort as the main driver, Haiku 5.5 at high effort for lookups and mechanical deletions.

**The constraint that shapes everything:** this is a Windows machine without Xcode. No agent can compile or run the app locally. The only compiler is GitHub's Mac build machines. So:

- every wave ends by pushing to one work branch and reading the GitHub build log;
- compile errors are fixed by small "fix packets" written from the saved log (one run per version of the files, per the slow-checks rule);
- the project rules' local tools (XcodeBuildMCP, the Codex `gh-fix-ci` skill) cannot run here. Build logs are read with `gh run view --log-failed`, which is what `gh-fix-ci` does.

**Branch and PR:** one branch, `fix/audit-2026-11-15`, and one pull request for the whole programme (agent rule: one PR per task). Each wave is one or more commits on it. Nothing is merged without Jack saying "publish".

**Why the audit's order changes in one place:** the audit says write the behaviour tests *before* the rework. Those tests would have to be written against the old screen-controller and then rewritten against the new one, and two of them (wrong-student saves, stale links) would fail on today's code by design. They are written once, against the new interface, in the same waves as the code they check (test-first within the package). The existing end-to-end UI test and unit suites protect the rework until then.

## 3. Target design

### 3.1 Data model (Issues 7, 20, 22; findings A-05–A-08, A-10, A-11, A-14, A-17)

One storage path: GRDB 7, one database file, one schema created by a single migration named `v1`. No JSON copy, no fallback store, no migration history (pre-production rule). `Configuration.foreignKeysEnabled` stays on (the default). In DEBUG builds only, `migrator.eraseDatabaseOnSchemaChange = true`.

UUIDs are stored as GRDB's default 16-byte blobs; dates as GRDB's default UTC text; arrays and nested value types as JSON text (GRDB does this automatically for `Codable` properties that are not database values). Every record type is a `Codable, FetchableRecord, PersistableRecord, Identifiable, Equatable, Sendable` struct with an explicit `static let databaseTableName`.

What is *not* stored any more because it can be worked out (agent rule 5):
- Totals (draft and final): always the sum of stored criterion points (product rule).
- Maximum points per criterion and criterion titles: read from the assignment's rubric.
- Scanned-text review status on the submission (lives only on `ocrDocument`; pasted text has `inputKind = pasted` and needs no review).
- Reviewed student text: built from `ocrLine` corrected/raw text; stored only as `pastedText` for pasted work.
- Roster status ("not started", "needs review", "draft ready", "approved"…): computed from the submission.
- Student name on submissions and roster rows; class name on students and assignments: joined at read time.
- Staleness: the current packet fingerprint is computed in memory when a submission is loaded or saved (SHA-256 of the assignment's setup plus the reviewed text) and compared with the fingerprint stored on the draft/final review. Nothing is re-encoded during screen drawing.

**Unreadable data** (Issue 7, A-08): GRDB's synthesized decoding throws on a bad enum value or bad UUID. Every hand-written `init(from:)` that swallows errors is deleted. A load failure surfaces `AppDatabaseError.dataCorrupted(table:, rowID:, underlying:)` to the blocking error screen (3.5). No defaults, no random IDs, no silently emptied lists.

### 3.4 Backup and restore files (Issues 6, 20; A-09, C-04, C-13, C-19, C-20)

- **Full backup (D5 = yes):** one Apple Encrypted Archive file, extension `.markformebackup`, password chosen by the teacher at export and asked for at restore. Contents: `manifest.json` (format version 1, created-at, app version, SHA-256 of every source file), `snapshot.json` (`BackupSnapshot` encoded once), `sources/<submissionID>/<file>`. LZFSE compression. Encryption: `ArchiveEncryptionContext(profile: .hkdf_sha256_aesctr_hmac__scrypt__none, compressionAlgorithm: .lzfse, compressionBlockSize: 1_048_576)` + `setPassword`. Wrong password → "That password doesn't open this backup." (D5 = no: same contents in a ZIP with `.deflate`.)
- **Teacher Record archive:** ZIP as today (opens on school PCs), written with ZIPFoundation's throwing `Archive(url:accessMode:)`, `.deflate`, entries added from memory (no temp file per entry). Contents: one `snapshot.json`, the Teacher Record Markdown/PDF, `sources/`.
- **Restore:** decode once into a `RestorePreview` that holds the decoded snapshot and the staging folder; Confirm uses that same object (no second decode, no re-fingerprint of the app's own staged file). Source files are extracted to `Application Support/RestoreStaging-<uuid>/` by reading archive entries one at a time and rejecting any entry that is not a regular file or directory (no symlinks) before writing it; path safety and size caps from `SourcePathSafety` are kept unchanged; manifest SHA-256 values are verified. Then the database transaction commits. Only after it commits, each staged file is moved into place with `FileManager.replaceItemAt(_:withItemAt:backupItemName:options:)`. On any failure before the commit, only the staging folder is deleted. Messages: failure before commit → "Restore failed. Your existing data and files are unchanged."; success → "Restore complete."
- Deleted: the legacy bare-JSON restore path, `assignments.json` fallback, the seven duplicate JSON files, `writeBundle`, the importer accepting `.json`/`.item` (it accepts only `.markformebackup`, or `.zip` if D5 = no).
